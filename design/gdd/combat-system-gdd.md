# 战斗系统 GDD（Combat System）
> 版本 v0.1 · MVP（Vertical Slice）· 作者 文策渊 · 关联《概念文档》《美术圣经 v0.2》
> 原创红线：★ 几何萌系剪影、灵兽技能池、灵囊/灵脉图谱命名，严禁复制任天堂/魔兽 IP 资产与命名。

---

## 1. 概述与目标
- **系统定位**：地窟内实时战斗子系统，是单局核心互动层。覆盖移动、自动普攻、手动技能、灵兽协同、敌人 AI、伤害结算与死亡/中断/元进度结算。
- **服务设计支柱**：
  - **P1 · 单手可玩，碎片友好** —— 操作收敛为「单虚拟摇杆 + 自动普攻 + 点按/滑动技能」，一只拇指完成一局；**不**做帧级走位或高频双指微操（红线）。
  - **P2 · 收集即成长，构筑即策略** —— 技能 / 灵兽 / 符文组合驱动策略深度，Build 来自组合而非倍率。
- **目标**：在移动端单手、单局 5–10 分钟约束下，提供「低操作频率、高策略密度」的战斗体验。

## 2. 核心机制
1. **移动** —— 单虚拟摇杆 8 向，角色自动朝向移动方向；角色自动锁敌最近的敌人。
   - 触屏映射：贴左/右下边缘「浮动摇杆（floating joystick）」，单指拖出；死区 15%。
2. **自动普攻** —— 锁定视野内最近敌人，按攻速 APS 自动发射，无需点按。
   - 触屏映射：无（全自动，红线：普攻不占用任何手动操作）。
3. **手动技能（MVP 2 个）** —— 技能①点按释放（锁定最近目标）；技能②滑动释放（沿滑动方向锥形 AoE）。带冷却环（外环顺时针缩减 + 中心数字倒计时）。
   - 触屏映射：右下角 2 个 ≥48px 按钮（建议 56×56）；滑动技能需在按钮热区内滑动位移 >12px 才判定，避免点按误触。
4. **灵兽协同** —— 队伍携带上限 3 只灵兽（从 4 只可驯服种类中选择，命名/定位以 `design/gdd/mvp-spirit-bestiary.md`（v1.2，审计后锁定）为准），各自技能池自动协战（AI 自动释放，玩家不手动控制）。★ 原创「灵兽技能池」，区别于宝可梦指令 / WoW 宠物。
5. **敌人 AI** —— 杂兵（追击近战）、精英（带阶段技）、Boss（多段技 + 场地机制）。
6. **伤害结算** —— 见 §3.5 公式。
7. **层间事件触发** —— 战斗胜利后开放出口事件（强化/招募/治疗），由层间抉择系统接管（属灵囊/元进度协作）。

## 3. 数据模型
### 3.1 主角 / 灵兽 基础属性
| 字段 | 单位 | 示例(主角「灯童」) | 说明 |
|---|---|---|---|
| hp | HP 点 | 100 | 生命值 |
| atk | 攻击力 | 12 | 基础攻击 |
| def | 防御 | 4 | 减伤输入 |
| spd | 格/秒 | 3.0 | 移动速度（1 格 = 16px 瓦片） |
| aps | 次/秒 | 1.2 | 自动普攻频率 |
| crit_rate | % | 5 | 暴击率 |
| crit_dmg | % | 150 | 暴击伤害 |

### 3.2 技能数据（skill 结构）
```
skill { id, name(原创), cast: tap|swipe, cd: 秒, coeff, target: nearest|cone|aoe, range: 格, rune_slots: 1–2 }
```
MVP 双技能：
- **灵击**（tap）：cd 4s，coeff 1.6，target=nearest（单体）。
- **缚灵**（swipe）：cd 8s，coeff 1.0，target=cone（前方 90° / 3 格）。

### 3.5 伤害公式（统一格式，单位标注）
```
Raw        = ATK × SkillCoeff                       // 攻击力 × 技能系数（无量纲）
Mitigated  = Raw × 100 / (100 + DEF × K)            // K = 8（减伤曲率常数，无量纲）
CritMult   = (crit_dmg / 100)  当 random() < crit_rate/100  否则 1.0
Variance   ∈ [0.90, 1.10]                            // uniform 随机（无量纲）
RuneMult   = Π(符文乘区)                             // 由灵囊符文提供，默认 1.0（见冲突 C1）
Final      = Mitigated × CritMult × RuneMult × Variance
Final      = clamp(Final, 1, 99999)                  // 每击伤害下限 1，防溢出
ΔHP        = floor(Final)                            // 向下取整到 HP 点
```
> 注：灵脉图谱 MODIFY_STAT 在 run 初始化时合成为 `BaseStat`（见冲突 C1），不进入每击实时计算。

## 4. 交互与操作
- **HUD 横屏（主推）**：左侧浮动摇杆；右下 2 技能按钮（56×56px，≥48 下限）；顶部主角血条 + 层数；Boss 战顶部 Boss 血条（圆角槽，<30% 切危险红 `#FF4D4D` 并脉冲 + 心形闪烁，见美术圣经 §4）。
- **HUD 竖屏（单手降级）**：信息压缩至底部，技能按钮移至屏幕下 1/3，摇杆浮动贴右下；信息密度降级（隐藏小怪血条，仅显示 Boss/精英）。
- **冷却环**：按钮外环顺时针缩减 + 中心数字倒计时；禁用态半透明 + 锁形图标（非仅变灰，呼应可访问性 Basic §7）。
- **误触容错**：按钮热区间距 ≥8px；滑动技能需位移 >12px 才判定；摇杆死区 15%。
- **左右手布局**：设置项可切换左手/右手单手握持布局。

## 5. 状态机/流程
```
[层载入] → [探索（无战斗）]
   ├─ 遇敌 → [战斗]
   │     ├─ 全灭敌人 → [清场] → 开放出口事件
   │     └─ 主角 HP ≤ 0 → [死亡]
   └─ 抵达出口（已清场）→ [层间抉择] → [下一层] 或 [通关段]
[死亡]      → 临时构筑清空 → 部分资源转永久货币（灵烬 ember_eternal）
[中断]      → 仅允许层间硬存档点保存；层内中断降级为「放弃本层」（见 §6 / 工程风险 E-A）
```
- **死亡结算**：本层临时掉落（灵兽/符文/物资实体）清空；临时货币 `coin_temp × 转化率` → `ember_eternal`（转化率待拍板，默认 30%）。
- **元进度**：`ember_eternal` 用于灵脉图谱节点激活（见灵脉 GDD）。

## 6. 边界与异常
1. **场景无敌人（目标为空）**：自动普攻进入 idle，不报错；摇杆仍可移动。
2. **程序生成失败（房间/路径异常）**：触发保底模板层（预制的 1 个安全层），不阻断流程；记录日志供工程排查（见工程风险 E-A）。
3. **数值溢出**：`Final` 经 `clamp(1, 99999)`；HP 上限 `clamp(0, max_hp)`；灵脉/符文合成时负 ATK/DEF 钳为 0。
4. **技能 CD 异常（CD≤0 或冷却中重复触发）**：以「帧末事件队列」结算，重复触发去重；CD 下限钳 0.5s 防卡死。
5. **队伍灵兽全灭但主角存活**：灵兽进入「休整」不可战，主角仍可普攻与放技能，不视为死亡。
6. **中断 / 存档损坏**：战斗中断以「放弃本层」降级，不写半截战斗状态；损坏回退至层间硬存档点（见 E-A）。

## 7. 美术/音效需求
- 引用《美术圣经 v0.2》：
  - 角色网格（§5）：杂兵 16×16、主角/灵兽 24×24、Boss 32–48；整数倍缩放，禁止非整数缩放导致像素错位。
  - 动画（§5）：待机/行走 4–6fps（循环 2–3 帧）；攻击/施法 6–8fps；特效态 ≤10fps。
  - 调色板（§2.2 / §5）：每场景 ≤16 色（取自 ≤32 母库子集），强制索引色。
  - 光向（§5）：统一「左上受光、右下阴影」；Boss 深层可局部向上熔岩橙 `#FF6A2C` 辉光作 accent。
  - 剪影语言（§3）：友方圆润稳定、敌方尖锐三角、Boss 破形；阵营靠形状 + 色彩双编码。
- **资产清单**：`char_tamer_{idle,walk,atk}_24`、`char_mossback_24`、`char_emberhorn_24`、`char_frostling_24`、`char_voltsprite_24`（命名以 `mvp-spirit-bestiary.md` 权威版为准，含 `_{idle,atk}` 变体）、`char_{mob}_idle_atk_16`、`char_boss_*_48`、`fx_spark_16`、`tile_*_16`、`ui_icon_*_24`。
- **音效**（交阮和鸣）：普攻 hit、技能释放、灵兽协战、Boss 登场屏震 + 熔岩橙辉光（§1 深层情绪）。

## 8. 可访问性
遵循 `docs/accessibility-requirements.md` Basic 级（Lean 强制），矩阵见该文第 2 节。本条落实其 §3.1–§3.5 五项必含项，与设计支柱无冲突（P1 单手操作的触控下限即来自此处）。冲突时以可访问性需求文件分级为权威（该文 §5）。

- **§3.1 形状 + 颜色双编码**：敌我/状态不依赖纯颜色。友方剪影圆润稳定（盾形/水滴形）+ 暖橙/天蓝；敌方尖锐三角 + 红/紫；Boss 破形（美术圣经 §3）。低血量、禁用技能、敌我区分均配图标/形状/动画。
- **§3.2 触控目标 ≥48px**：虚拟摇杆浮动贴边、技能按钮 56×56（≥48 下限）、热区间距 ≥8px（美术圣经 §4）；左/右手单手布局可切换。
- **§3.3 色盲安全配色**：危险/安全不用纯红/纯绿对立；危险红 `#FF4D4D` 须配形状提示；主调色板经 CVD（红绿/蓝黄/全色盲）模拟验证（美术圣经 §2.2 / §7）。
- **§3.4 非色彩提示**：血条 <30% 切危险红 `#FF4D4D` 并脉冲，叠加「心形闪烁 / 屏边红框」；技能冷却中半透明 + 锁形图标 + 环形遮罩（非仅变灰）。
- **§3.5 最小可读字号 ≥14px**：HUD 正文 ≥14px（@1x 逻辑）、标题 ≥18px；像素字体提供 ≥14px 渲染档（美术圣经 §7）。
- **灵兽种族识别**：靠三角特征（耳/角/尾位置·数量·朝向）而非仅配色，与 `design/gdd/mvp-spirit-bestiary.md`（美术负责人林绘澄产出）一致，本 GDD 仅引用不重复定义。

## 9. 验收标准 + 待工程确认项
**验收标准**：
1. 单摇杆 + 自动普攻 + 2 技能可在单手完成一局；
2. 5 层地窟程序生成可玩通；
3. 伤害公式一致无溢出、无负伤害；
4. 死亡可正确回庇护所并转化货币。

**待工程确认（程基岩 · 架构评审）**：
- **E1 程序生成地窟**：Godot 4 TileMap + 种子化生成的可靠性与性能；生成失败保底策略开销。
- **E2 触屏输入并发**：摇杆 + 2 按钮 + 滑动 + 自动普攻同帧输入仲裁，低端机帧预算。
- **E3 自动战斗 AI 开销**：多实体（主角 + ≤3 灵兽 + 杂兵群）寻路/锁敌的 tick 频率与省电策略。
- **E4 可中断存档**：层间硬存档点序列化方案（种子 + 事件日志 vs 全状态）。

> **灵兽命名 / 定位权威声明**：本文战斗系统 GDD 中灵兽命名与定位（苔背 Mossback / 焰角 Emberhorn / 霜铃 Frostling / 雷隼 Voltsprite）以 `design/gdd/mvp-spirit-bestiary.md`（v1.2 权威版，art-director 产出）为准；技能 / 数值 / 交互待该文件 §7 回填。
