- **权威锚点来源**：视觉锚点以《概念文档》第 7 节为准；本文第 1、3、9 章据此重写对齐。
- **原创性红线（★ 原创改造点）**：宝可梦（《Pokémon》）/ 任天堂角色·名称·精灵图·招式名，以及魔兽世界（《WoW》）具体贴图·图标·字体·LOGO，一律禁止复制。本作仅**借鉴其"语言"**——

## 1. 世界观与视觉基调
**整体氛围**：怀旧温暖中带冒险感（概念文档语），明快、饱和但不阴郁恐怖。地窟探索由浅入深，情绪从"安全好奇"递进到"压迫高潮"，收集与构筑贯穿全程。

**时代感**：非历史、非科幻的架空"低魔奇想（Low-Fantasy Whimsy）"——火把 + 符文 + 简单机械，无现代工业元素；美术上承接宝可梦式"绒毛萌感 + 场景色块情绪"，但轮廓全部原创几何化。

**情绪目标分层（对齐概念文档三层色彩情绪板，详见第 2.1）**
| 场景层 | 情绪 | 视觉手段 |
|---|---|---|
| 地窟上层 | 安全 / 好奇 | 晨雾青绿 + 暖黄光斑，柔和体积光，圆润剪影 |
| 地窟中层 | 神秘 / 紧张 | 暮紫 + 琥珀，冷暖交界，体积光收窄、轮廓趋锐 |
| Boss 深层 | 压迫 / 高潮 | 冷靛 + 熔岩橙，强对比、锐利边缘、屏震 |
| 庇护所 / 营地 | 治愈 / 收集欲 | 暖橙 + 奶白，柔光、符文灯彩 UI |
| 战斗瞬间 | 爽快 / 节奏 | 粒子高光、补间夸张、冷却环提示 |

**视觉锚点（已对齐概念文档第 7 节）★★★★ 原创改造**
- 锚点 A「几何萌系驯导者」：24×24，圆角矩形躯干 + 三角耳/角/尾特征；主角驯导者以「小斗篷 + 灵囊挂饰」剪影辨识，暖橙 `#FF8C42` + 奶白 `#F4E4C1`。
- 锚点 B「三层色彩情绪板」：上层 晨雾青绿 + 暖黄光斑 → 中层 暮紫 + 琥珀 → Boss 深层 冷靛 + 熔岩橙；整体怀旧温暖带冒险感。
- 锚点 C「符文灯彩 UI · 灵囊/灵脉图谱」：原创"符文灯彩"框体承载 WoW 式信息密度（灵囊三栏、灵脉图谱节点），图标全原创不搬。
- 锚点 D「抖动手作感」：1–2px 描边 + 2×2 抖动渐变，4–6fps 低帧待机/行走，强调手作像素感。

## 2. 色彩系统（宝可梦式情绪板 · 原创化）
策略核心：**明快饱和但不过曝**（概念文档硬约束）。全部颜色控制在"鲜亮但不刺眼"区间，用明度层级而非灰阶区分体积；高光避免纯白 `#FFFFFF`，改用带色相的近白（如羊皮暖白）防止过曝。

### 2.1 三层色彩情绪板（对齐概念文档第 7 节 · 场景色主轴）
| 地窟层 | 情绪 | 主色对 | Hex（主 / 辅） | 用途 |
|---|---|---|---|---|
| **上层** | 安全 / 好奇 | 晨雾青绿 + 暖黄光斑 | `#7BC9B0` / `#FFD23F` | 地表、安全区、探索光斑 |
| **中层** | 神秘 / 紧张 | 暮紫 + 琥珀 | `#7A5E9E` / `#D98E32` | 谜题层、稀有、紧张转场 |
| **Boss 深层** | 压迫 / 高潮 | 冷靛 + 熔岩橙 | `#2B3A66` / `#FF6A2C` | 深渊背景、Boss 战、高光辉度 |

> 三层递进 = 由"冷青绿暖黄"渐入"冷靛熔岩"，整体保持暖怀旧底色，避免阴郁恐怖。

### 2.2 主调色板母库（Master Palette，跨场景共享，≤32 色）

### 2.3 明暗与饱和度策略
- **明度阶梯**：每个主色至少 3 级（暗 / 中 / 近白高光），用羊皮暖白 `#F4E4C1` 作高光而非纯白，体积塑造避免平涂与过曝。
- **饱和度封顶（不过曝）**：主体饱和 **60%~88%**；背景饱和降至 **35%~55%** 拉开前后景；全屏禁止纯 `#FFFFFF` 高光块。
- **冷暖平衡**：暖色主导前景（亲和），冷色主导背景（空间），三层情绪板已内建冷暖递进。
- **每场景 ≤16 色硬性约束**：从 2.2 母库取子集；跨场景复用母库保证整体统一（详见第 5 章）。

## 3. 角色与怪物剪影语言（★ 原创"几何萌系"）
> 核心改造点：以"几何萌系"替代宝可梦具体轮廓——**圆角矩形躯干 + 三角耳/角/尾**作特征识别，大头身比 Q 版。全部角色为地窟原生灵兽，无任天堂版权资产。

**原创像素角色设计准则**
1. **几何萌系骨架**：躯干=圆角矩形（或圆角方块），特征器官=三角耳/角/尾，三者组合即"种族识别码"。区别于宝可梦圆润生物轮廓，是 ★ 版权规避点。
2. **大头身比 Q 版**：头身比约 1:1.2~1:1.5，头略大、身方正，亲和易辨识；表情仅用 2–3 像素眉眼变化传达。
3. **轮廓辨识度（Silhouette Readability）**：每个角色在 24×24 甚至缩到 16×16 时，仅凭黑色剪影即可区分阵营与类型。
   - 友方/伙伴：上窄下宽"圆润稳定"剪影（盾形、水滴形）。
   - 敌对杂兵：尖锐、不对称、带三角刺/角（锯齿、倒三角）。
   - BOSS：超大占比 + 独特破形（多足、悬浮核心）。
4. **主角驯导者专属剪影**：「小斗篷 + 灵囊挂饰」——斗篷给出飘动轮廓辨识，腰间灵囊挂饰强化职业识别，是玩家长线代入锚点。
5. **阵营色彩区分**：友方偏暖橙/天蓝，敌方偏红/紫/熔岩橙；**必须配合形状而非仅靠颜色**（满足可访问性，见第 7 章）。
6. **动作剪影**：攻击帧在剪影层面体现"蓄力→释放"夸张形变（三角特征张开/收拢），而非仅颜色变化。

## 4. UI 视觉规范（WoW 信息密度 · 原创"符文灯彩"）
> 借鉴 WoW 的**信息密度与装备质感**用于「灵囊」与「灵脉图谱」的图标语言，但 ★ 图标全原创、命名全原创，不搬任何 WoW 资产。

**风格定位**：原创"符文灯彩（Rune-Lantern）"——暖铜描边 + 内嵌发光符文，替代魔兽金属铆钉感；圆角更柔、发光更暖，契合移动端亲和基调与"驯导者+灵兽"奇幻感。

**面板（Panel）**
- 外框：2px 暖铜 `#A56A43` + 1px 内描边 `#FFD23F`（低透明发光），圆角 8px。
- 底材：暮蓝 `#2B2F4A` 80% 不透明 + 顶部 1px 高光。
- 分区：细符文线（1px 半透明 `#FFD23F`）分隔，不用重黑线。

**图标（Icon）★ 原创**
- 基准 24×24（列表小图 16×16，大图 32×32），统一 1–2px 深色描边 + 左上 1px 高光。
- 物品图标须含"类别角标"（灵兽/符文/物资用不同形状角标，非仅颜色）——适配 WoW 式高密度但原创形状语言。

**灵囊（替代 WoW 方格背包）**
- 三栏分类：灵兽 / 符文 / 物资；每栏网格化收纳，降低触屏整理负担。
- 栏目标签用原创符文图标 + 文字，色块区分三栏（配合形状，非仅色）。

**灵脉图谱（替代 WoW 天赋树）**
- 节点：视觉直径 **44px** 圆形（保留视觉语言），未激活陶土棕 `#A56A43`，已激活暖橙 `#FF8C42` + 外发光；命名/布局全部原创（灵脉主题）。**触控命中区须 ≥48×48px**（透明 padding / 命中半径 48px，见 `docs/accessibility-requirements.md` §3.2），节点间距 ≥8px 防热区重叠。
- 连线：2px 发光符文线，激活段用 `#FFD23F`；径向/树状分支，节点大小表层级。

**进度条 / 血条**
- 圆角矩形槽（暮蓝底），填充用主色渐变；低于 30% 切危险红 `#FF4D4D` 并脉冲。
- **关键状态必须配非色彩提示**：低血量加"心形闪烁/屏边红框"，不可只靠变红。

**技能面板（灵兽技能池 + 主角灵脉）**
- 网格 4×N，每格 64×64 圆角框；技能图标居中，冷却用环形遮罩（顶部顺时针缩减）+ 数字倒计时。

**移动端触控目标最小尺寸**
- **硬性下限 48×48px**（满足 Apple HIT 44pt 与 Android 48dp）。
- 主操作（技能/确认）建议 56~64px；列表项行高 ≥56px；相邻可点元素间距 ≥8px，避免误触。

## 5. 像素规格（对齐概念文档第 7 节）
**网格基准**
- 瓦片（Tile）：`16×16`（地图基础单元，整数倍拼接）。
- 杂兵 / 小灵兽：`16×16`。
- 主角驯导者 / 主要灵兽：`24×24`（★ 几何萌系主角单元）。
- BOSS / 大型单位：`32×32` 或 `48×48`（=16/24 的整数倍，引擎中按整数倍缩放显示，禁止非整数缩放导致像素错位）。
- UI 图标：基准 `24×24`，小图 `16×16`，大图 `32×32`。

**调色板上限（硬性）**
- **每场景调色板 ≤16 色**（对齐 PICO-8 / 概念文档克制语言）；从母库（第 2.2，≤32）取子集。
- 强制索引色（Indexed Color），导出 PNG-8 / 带调色板，避免导入 Godot 后偏色。

**轮廓与抖动（Dithering）**
- **1–2px 深描边**：16×16 用 1px，24×24 及以上用 2px（取 `#1A1C2C` 或资产最暗色近似），方向一致（默认**左上受光、右下阴影**——已与概念文档作者确认采纳为全项目统一光向；Boss 深层可局部叠加向上熔岩辉光作 accent，不破坏全局光向；最终由主理人终审）。
- 明暗过渡用 **2×2 棋盘抖动**（中性岩灰 `#9AA0B5` 参与）而非渐变带，保持手作颗粒感；禁止抗锯齿羽化（AI 生成图必须去抗锯齿后处理）。

**动画帧率（手作低帧）**
- 待机/行走：**4–6 fps**（循环 2–3 帧），强调手作像素感（概念文档硬约束）。
- 攻击/施法：可略升至 6–8 fps；特效态 ≤10 fps（移动端省电优先）。
- 所有动画帧**必须同调色板、同网格对齐**，逐帧位移为整数像素（no sub-pixel）。

## 6. AI 生成资产规范（重点章节）
> 本项目所有美术资产由 AI 生成。AI 产出的"伪像素图"本质是**先生成高分辨率图再像素化降采样**，需严格锁定风格与后处理链路，否则跨帧/跨角色会严重不一致。

### 6.1 风格锁提示词框架（Style-Lock Prompt Framework）
**三层锁结构，每生成一张图都固定以下变量：**

```
[1] 风格锁（固定，所有提示词复用同一段）
"original pixel art, 16x24 grid sprite, clean 1-2px dark outline,
flat cel shading, 2x2 dithering, limited 16-color palette (PICO-8-like restraint),
no anti-aliasing, crisp pixel edges, retro handheld aesthetic -- NOT Nintendo IP,
geometric-cute original creature (rounded-rect body + triangular ears/horns/tail)"

[2] 内容描述（每次变化）
"a tamer protagonist with small cloak and spirit-pouch pendant, warm orange tunic,
facing front, idle pose, on transparent background"

[3] 负向锁（固定）
"--no blur, --no gradient smoothing, --no jpeg artifacts, --no anti-aliasing,
--no photorealistic, --no 3d render, --no pokemon, --no nintendo,
--no world-of-warcraft icon, --no copyrighted character"
```

**一致性控制手段**：
- **固定种子（Seed）**：同类资产（同一角色不同动作）使用同一 base seed + 仅变动作词，保证脸/体型不变。
- **风格词常量化**：把 [1] 风格锁与 [3] 负向锁存为模板变量，禁止逐次改写。
- **参考锁定**：首张"金标准"图定稿后，后续用 **image-to-image + 低 denoise（0.2~0.35）** 在其基础上改动作/配色，而非从文本重新生成。
- **后处理强制链路**：AI 出图 → 缩放到目标网格 16/24（最近邻）→ 套用场景 ≤16 色子集索引 → 补 1–2px 描边 → 2×2 抖动降色。该链路写成脚本，人工不可跳过。

### 6.2 一致性校验清单（每批资产交付前逐项打勾）
| # | 检查项 | 标准 | 工具/方法 |
|---|---|---|---|
| 1 | 轮廓一致 | 同角色不同帧轮廓误差 ≤1px | 叠加半透明比对 |
| 2 | 调色板一致 | **每场景 ≤16 色**、且取自母库、无偏色 | 索引色统计脚本 |
| 3 | 光照方向 | 全部默认"左上受光、右下阴影" | 目视 + 高光位检查 |
| 4 | 像素网格对齐 | 无半透明像素、无亚像素偏移 | 放大 800% 检查 |
| 5 | 描边统一 | 1–2px 同色描边，无断裂 | 描边层提取比对 |
| 6 | 无 IP 残留 | 无宝可梦/任天堂/魔兽具体元素 | 人工 + 反向图搜抽检 |

### 6.3 商用授权条款与风险说明（关键风险点）
**风险一：版权/训练数据污染**
- 多数文生图模型在含受版权像素美术的数据上训练，直接生成"宝可梦风"存在**风格近似即可能构成近似表达**的侵权边界风险；且平台对"AI 生成内容是否可版权"立场不一。
- **可控落地方案**：
  1. 全程保留"人类创意主导"证据链（本圣经即创作意图文档 + 提示词版本记录 + 后处理脚本），将资产定性为"人类指导下的演绎作品"。
  2. 严格规避任何可识别 IP（人物、名称、招式、LOGO）；只用抽象"调色板/剪影语言"借鉴；★ 几何萌系为原创改造点，强化差异。
  3. 商用前做一次**反向图搜 + 法务抽检**，确认无显著近似既有商业角色。

**风险二：平台政策**
- **Steam**：允许 AI 生成内容，但需在商店页披露"使用 AI 生成美术"；整体对原创独立游戏友好。
- **App Store（iOS）**：Apple 要求所有内容不侵权、不抄袭；AI 生成若含可识别第三方 IP 会被拒；须确保无未成年人向侵权内容。
- **Google Play（Android）**：要求"不误导、不侵权"，AI 内容需可声明。
- **建议合规动作**：①商店页统一标注"Art assets AI-assisted, human-directed"；②建立资产来源登记表（seed/提示词/日期）；③预留法务复核预算；④核心角色（驯导者 + 主要灵兽）建议**最终由人工重绘/精修**一版"金标准"以强化原创性主张。

## 8. 资产命名与目录约定
> 对接 Godot 4 工程与 AI 生成流水线。命名全小写 + 下划线，便于跨平台与脚本批处理。

**目录结构（资产根 `/assets`）**
```
/assets
  /sprites
    /characters   # 角色与怪物（按实体名分子目录）
    /props        # 道具/可互动物
    /tiles        # 地图瓦片（地表/墙体/装饰）
    /effects      # 粒子贴图/光斑
  /ui
    /icons        # 物品/技能图标（灵囊/灵脉图谱）
    /panels       # 面板框/进度条/灵脉节点
    /fonts        # 像素字体
  /reference      # 金标准图、风格锁样本（不入工程）
```

**命名规则 `{category}_{entity}_{variant}_{size}.png`**
| 段 | 取值示例 | 说明 |
|---|---|---|
| category | `char` / `tile` / `ui` / `fx` | 大类 |
| entity | `tamer` / `slime_r` / `grass` | 实体/材质名（snake_case） |
| variant | `idle` / `walk` / `atk` / `a01` | 动作或变体 |
| size | `16` / `24` / `48` | 像素网格尺寸（角色单元 16/24） |

示例：
- `char_tamer_idle_24.png`、`char_tamer_atk_24.png`（同 seed 系列）
- `char_slime_r_idle_16.png`（小灵兽 16×16）
- `tile_grass_16.png`、`tile_wall_dark_16.png`
- `ui_icon_rune_24.png`、`ui_talent_node_44.png`
- `fx_spark_16.png`

**AI 流水线对接**：生成原始图存 `/assets/reference/_raw/{entity}_{seed}_{ts}.png`，经后处理脚本（第 6.1）输出到正式目录并登记到 `asset-manifest.csv`（含 seed、提示词摘要、日期、所属场景、一致性校验结果）。
